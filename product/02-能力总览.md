## 1. 协议与端点

### 1.1 文本协议

New API 支持四套主流文本协议，并在它们之间做双向转换——客户端用哪套都行，上游用哪套都行。

| 接口 | 端点 | 说明 |
| --- | --- | --- |
| **OpenAI Chat** | `POST /v1/chat/completions` | 最通用的入口，绝大多数客户端走这里 |
| **OpenAI Responses** | `POST /v1/responses` | 新一代 Responses 协议，支持流式 / 同步 / 后台三种模式 |
| **OpenAI Responses (WS)** | `GET /v1/responses` | WebSocket 升级；渠道选择在首个 `response.create` 事件之后进行 |
| **Anthropic Messages** | `POST /v1/messages` | Claude 原生协议 |
| **Gemini** | `POST /v1beta/models/{model}:generateContent`、`POST /v1beta/models/{model}:streamGenerateContent` | Gemini 原生协议 |
| **Realtime (WS)** | `GET /v1/realtime` | 实时语音 WebSocket |
| **Responses 压缩** | `POST /v1/responses/compact` | 上下文压缩 |
| **独立搜索** | `POST /v1/alpha/search` | 独立网页搜索 |

### 1.2 多模态与其他能力

| 接口 | 端点 | 说明 |
| --- | --- | --- |
| **图片生成** | `POST /v1/images/generations`、`POST /v1/images/edits` | 经任务插件协议接入；未声明该协议的模型回落到常规转发 |
| **语音合成** | `POST /v1/audio/speech` | TTS |
| **语音转写** | `POST /v1/audio/transcriptions` | ASR，同步阻塞 |
| **语音翻译** | `POST /v1/audio/translations` | 音频翻译 |
| **文本嵌入** | `POST /v1/embeddings` | 向量化 |
| **重排序** | `POST /v1/rerank` | Rerank 模型 |
| **内容审核** | `POST /v1/moderations` | Moderation |
| **通用补全** | `POST /v1/completions` | 旧式补全接口 |
| **图片编辑（旧版）** | `POST /v1/edits` | OpenAI 旧版图片编辑入口，走图片格式转换路径 |
| **模型列表** | `GET /v1/models`、`GET /v1/models/{model}` | 按令牌分组过滤可见模型 |
| **Gemini 模型列表** | `GET /v1beta/models` | Gemini 兼容 |

### 1.3 异步任务

| 接口 | 端点 | 说明 |
| --- | --- | --- |
| **任务提交** | `POST /v1/tasks/{pluginKey}` | 通用任务提交，路径携带插件 key |
| **任务查询** | `GET /v1/tasks/{taskId}` | 查询任务状态 |
| **任务产物** | `GET /v1/tasks/{taskId}/artifacts`、`GET /v1/tasks/{taskId}/artifacts/{artifactKey}/content` | 列出与下载产物 |
| **视频** | `POST /v1/videos`、`GET /v1/videos/{taskId}`、`GET /v1/videos/{taskId}/content` | 视频任务协议 |
| **音频任务** | `POST /v1/audio/transcriptions/tasks`、`GET /v1/audio/transcriptions/tasks/{taskId}` | 异步转写 |
| **图片（任务插件协议，同步返回）** | `POST /v1/images/generations`、`POST /v1/images/edits` | 走任务插件协议的图片入口，但请求内直接返回最终图片，**非异步轮询** |

此外每个插件可自行声明额外路由。详见 [06-异步任务与插件](06-异步任务与插件.md)。

### 1.4 显式未实现

以下 OpenAI 兼容端点被显式声明为未实现，返回明确错误而非静默伪装：

- `/v1/files` 全系列（GET / POST / DELETE / content）
- `/v1/fine-tunes` 全系列
- `/v1/images/variations`
- `DELETE /v1/models/{model}`

### 1.5 关于协议转换的重要说明

**转换不是无损的。** 具体可用特性取决于渠道、上游模型与转换路径；协议特有的工具与字段可能无法精确映射。WebSocket 支持还要求上游与渠道配置同时兼容。

这是设计上的取舍——New API 保证的是"主流用法可跨协议工作"，而不是"任意字段无损透传"。深度依赖某家私有字段的客户端，应直连该上游。

## 2. 功能矩阵

### 2.1 六大能力域

| 能力域 | 能做什么 |
| --- | --- |
| **模型接入** | OpenAI Chat Completions、Responses、Anthropic Messages、Gemini API；流式响应；工具调用、推理内容、多模态输入（视上游支持） |
| **路由调度** | 模型映射、渠道优先级与权重、重试、渠道亲和、多上游密钥 |
| **用量与成本** | 配额管理、订阅、使用日志、缓存计量、按用量档位的表达式计费 |
| **访问控制** | 用户管理、分组、细粒度权限、API 密钥限制；OAuth/OIDC、Passkey、双因素认证、登录会话管理 |
| **异步任务** | 用 JavaScript 插件扩展图片、视频等任务 API，含任务状态与产物获取 |
| **Web 控制台** | 配置渠道与模型、查看用量与审计日志、在 Playground 试用模型；英 / 简中 / 繁中 / 法 / 日 / 俄 / 越 共 7 语言 |

### 2.2 路由调度能力细项

| 能力 | 说明 |
| --- | --- |
| 模型映射 | 把请求模型名改写为上游实际模型名，一个渠道可承接多个业务模型名 |
| 优先级 | 数值越大越优先，同优先级内进入权重分配 |
| 权重 | 同优先级渠道间的分流比例 |
| 重试 | 上游失败时按规则换渠道重试 |
| 渠道亲和 | 让同一会话稳定落到同一渠道，避免缓存失效与上下文割裂 |
| 多 Key 池 | 单渠道挂多把密钥，支持轮询、随机、故障剔除 |

### 2.3 用量与成本能力细项

| 能力 | 说明 |
| --- | --- |
| 配额 | 用户级与令牌级额度，额度不足即拒绝 |
| 订阅 | 周期性额度包，按用户绑定并自动抵扣 |
| 使用日志 | 完整请求记录，含用量、费用、渠道、耗时 |
| 缓存计量 | 缓存命中与创建的 token 分别计量与计价 |
| 表达式计费 | 按用量档位、分组、缓存、图片、音频等维度组合定价 |

### 2.4 访问控制能力细项

| 能力 | 说明 |
| --- | --- |
| 用户与角色 | 多级角色体系 |
| 分组 | 分组决定可见模型、可用渠道与计费倍率 |
| 细粒度权限 | 基于策略的授权，管理面与数据面分离 |
| 密钥限制 | 令牌可限定模型、额度、有效期、分组 |
| 认证方式 | OAuth/OIDC、Passkey、双因素认证、会话管理 |

## 3. 管理 API 分组

管理接口统一挂载在 `/api` 下，按域划分：

| 分组前缀 | 用途 |
| --- | --- |
| `/api/channel` | 渠道 CRUD、批量操作、标签管理、测试、余额刷新、密钥查看、多 Key 管理、上游模型同步（40+ 条路由） |
| `/api/user` | 用户与自身账户。`/api/user/self*` 为当前用户接口；`/api/user`、`/api/user/:id` 等为管理员接口（两者由鉴权中间件区分，而非不同前缀） |
| `/api/token` | 令牌 CRUD、搜索、额度调整 |
| `/api/usage/token` | 令牌用量查询 |
| `/api/log` | 消费日志与系统日志查询 |
| `/api/audit` | 管理操作审计（`/api/audit/self` 为本人操作） |
| `/api/authz` | 权限目录（`/api/authz/catalog`） |
| `/api/data` | 仪表盘数据统计 |
| `/api/group` | 分组管理 |
| `/api/prefill_group` | 分组预填规则 |
| `/api/models` | 模型列表与元数据 |
| `/api/vendors` | 供应商管理 |
| `/api/deployments` | 部署管理 |
| `/api/option` | 系统选项配置 |
| `/api/ratio_sync` | 倍率同步（`/channels` 与 `/fetch`） |
| `/api/subscription` | 订阅管理；下分 `/subscription/admin` |
| `/api/redemption` | 兑换码管理 |
| `/api/task` | 任务查询 |
| `/api/system-task` | 系统任务 |
| `/api/concurrency` | 并发状态观测：快照 / 历史 / 路由健康（**只读**；并发阈值与排队参数经 `/api/option` 配置） |
| `/api/perf-metrics` | 性能指标 |
| `/api/performance` | 性能统计与运维操作（Root 权限） |
| `/api/plugin/task` | 任务插件管理 |
| `/api/custom-oauth-provider` | 自定义 OAuth 提供方 |
| `/api/system-info` | 系统信息 |
| `/api/mj` | Midjourney 相关 |

另有 `/api/status`、`/api/setup`、`/api/pricing`、`/api/rankings` 等顶层接口，以及支付回调（Stripe / Creem / Waffo / 易支付）、邮箱验证、密码重置等认证类接口。

> 路由数量随功能迭代变化，此处按域列举而非给出精确条数。

## 4. 控制台模块

Web 控制台共 28 个功能模块（`web/src/features/`）：

| 分类 | 模块 |
| --- | --- |
| **模型与接入** | channels（渠道）、models（模型）、model-pricing（模型定价）、pricing（定价展示）、task-plugins（任务插件） |
| **用量与成本** | usage-logs（使用日志）、performance-metrics（性能指标）、redemption-codes（兑换码）、subscriptions（订阅）、wallet（钱包）、rankings（排行榜） |
| **访问与安全** | users（用户）、keys（密钥）、auth（认证）、security（安全中心）、profile（个人资料） |
| **运维** | concurrency（并发治理）、dashboard（仪表盘）、system-settings（系统设置）、system-info（系统信息）、system-update（系统更新）、errors（错误页） |
| **体验** | home（首页）、chat（对话）、playground（调试）、about、legal、setup |

## 5. 计费维度

New API 的计费不是"按请求数"，而是按**上游真实返回的用量**：

| 维度 | 说明 |
| --- | --- |
| 输入 token | 基础计价变量 |
| 输出 token | 基础计价变量 |
| 缓存读取 / 创建 | Claude 等支持缓存的模型可单独计价，含不同 TTL 档 |
| 图片 | 按张数，可区分输入与输出 |
| 音频 | 输入 / 输出音频 token 或时长 |
| 工具调用 | Responses 等协议的内置工具调用次数可附加计费 |
| 固定价 | 按次计价，须作为完整叶子价：`tier("request", fixed(0.01))`（Realtime 与任务用量表达式不接受 `fixed()`） |

完整机制见 [05-计费与配额](05-计费与配额.md)。
