# 05 · 计费与配额

> [← 返回目录](README.md)

---

## 1. 定位

计费回答三个问题：**这次该收多少钱**、**这个用户还剩多少**、**算错了怎么发现**。

New API 的计费不是"按请求数"，而是按**上游真实返回的用量**。同一个模型换一家供应商，用量口径不同但价格可对齐；同一个请求走不同倍率组合，费用差异可追溯。

---

## 2. 两套计费模式

系统支持两种计费模式，可按模型分别配置。

| 模式 | Key | 说明 |
| --- | --- | --- |
| **倍率计费** | `ratio` | 传统倍率表方式：模型倍率 × 分组倍率 × 完成倍率。兼容历史配置 |
| **表达式计费** | `tiered_expr` | 用一行表达式完整描述计费逻辑，支持阶梯、缓存、图片、音频等维度（工具调用附加费在表达式之外单独计算） |

未显式配置时：已知内置定价模型走表达式计费——但若该模型已被管理员配置过模型倍率或固定价，仍**优先走倍率计费**；其余模型走倍率计费。

---

## 3. 表达式计费

### 3.1 设计原则

> **一条表达式，一个真相。**

一条表达式字符串完整定义一个模型的计费逻辑——定价、阶梯条件、缓存/图片/音频区分、按时折扣、请求感知的乘数，全部在一行里。没有散落的配置，没有隐式规则，没有魔法数字。

| 原则 | 含义 |
| --- | --- |
| **表达式自包含** | 表达式字符串单独决定计费。同样用量 + 同样上下文 → 同样费用 |
| **变量按需启用** | `p`（输入）与 `c`（输出）是基础，缓存/图片/音频变量可选。系统用 AST 内省自动识别表达式用到的变量，并据此调整 token 归一化 |
| **价格是真实价格** | token 系数就是供应商公布的 $/1M tokens。`p * 2.5` 就是每百万输入 token 2.5 美元 |
| **与上游无关** | OpenAI 格式（prompt_tokens 含缓存）与 Claude 格式（input_tokens 不含缓存）的差异由系统消化 |
| **版本化** | 表达式带 `v1:` 版本标签，版本控制编译环境、token 归一化与配额换算公式，可演进而不破坏存量表达式 |

### 3.2 可用变量

| 变量 | 含义 |
| --- | --- |
| `p` | 输入 token 数（计价用），自动排除表达式中单独计价的子类别 |
| `len` | 输入上下文总长度（条件判断用），始终反映完整输入长度 |
| `c` | 输出 token 数 |
| `cr` | 缓存命中（读取）token 数 |
| `cc` | 缓存创建 token 数（Claude 5 分钟 TTL / 通用） |
| `cc1h` | 缓存创建 token 数，1 小时 TTL（Claude 专用） |
| `img` | 图片输入 token 数 |
| `img_cr` | 图片缓存读取 token 数 |
| `img_o` | 图片输出 token 数 |
| `ai` / `ao` | 音频输入 / 输出 token 数 |

### 3.3 表达式语言

基于 `expr-lang/expr`，提供：

| 能力 | 示例 |
| --- | --- |
| 算术与比较 | `p * 2.5 + c * 10` |
| 条件分支 | `len <= 272000 ? ... : ...` |
| 阶梯定价 | `tier("standard", p * 10 + c * 50)` |
| 固定价 | `fixed(0.01)` |
| 变量识别 | 系统自动检测表达式引用了哪些变量 |

### 3.4 实际示例

内置定价（价格取自供应商公开定价页）：

```text
gpt-image-2:
  tier("standard", p * 5 + cr * 1.25 + img * 8 + img_cr * 2 + c * 30)

gpt-6-astra:
  len <= 272000
    ? tier("standard", p * 10 + c * 50 + cr * 1 + cc * 12.5)
    : tier("long_context", p * 20 + c * 75 + cr * 2 + cc * 25)
```

长上下文阶梯的费率**适用于整个请求**，而非只对超出部分。

> **注意**：不要从请求参数推导服务档位折扣——渠道默认会过滤 `service_tier`，该参数可能根本没传到上游。

### 3.5 插件计费表达式

任务插件可声明自己的计费表达式（`plugin_billing_expr`），按插件实际返回的用量事实结算，例如：

- 视频：按生成秒数
- 图片：按生成张数
- 音乐：按时长
- 语音：按音频秒数

## 4. 倍率体系

倍率计费模式下，各倍率**作用于对应的 token 分项**，而不是整体相乘：

```
费用 = (输入 token
      + 缓存 token × 缓存倍率
      + 图片/音频分项 × 对应倍率
      + 输出 token × 完成倍率)
     × 模型倍率 × 分组倍率 × (其他倍率)
```

| 倍率 | 作用 |
| --- | --- |
| **模型倍率** | 模型的基准单价，乘在分项汇总之后 |
| **完成倍率** | **只作用于输出 token** |
| **缓存倍率** | **只作用于缓存 token**（命中与创建可分别配置，命中价通常低于输入价） |
| **分组倍率** | 按用户分组定价——vip 与普通用户可以不同价 |
| **group-to-group 倍率** | 用户分组走另一分组时的转移系数，实现内部转移定价 |
| **其他倍率** | 图片张数、分辨率、质量、视频时长等请求相关乘数 |

> **倍率与表达式的关系**：同一模型两种模式不能混用。配置为 `tiered_expr` 的模型走表达式路径，其倍率表条目不生效。

## 5. 配额安全不变量

这是计费模块最核心的部分。以下约束不可违背：

### 5.1 换算集中

所有配额换算必须走 `common/quota_math.go` 的受控函数，**禁止裸类型转换**：

| 函数 | 用途 |
| --- | --- |
| `QuotaFromFloat` | 浮点乘积转整型（向零截断） |
| `QuotaRound` | 需要四舍五入时（半数远离零） |
| `QuotaFromDecimal` | 十进制乘积转整型 |
| `WalletQuotaFromDecimalStrict` | 钱包/充值金额转换，限制在 JavaScript 安全整数范围 |

`QuotaFromFloat` / `QuotaRound` / `QuotaFromDecimal` 各有一个 `*Checked` 变体（额外返回截断标记，用于审计）与一个 `*Strict` 变体（饱和时返回错误而非放行）；`WalletQuotaFromDecimalStrict` 没有 `*Checked` 变体。

### 5.2 乘数有界

所有会成为计费乘数的用户可控量，都必须在**请求校验层**设上界，越界返回 400：

| 字段 | 约束 |
| --- | --- |
| 图片生成张数 `n` | `dto.MaxImageN` |
| 视频时长 / 秒数 | `relaycommon.MaxTaskDurationSeconds` |
| `max_tokens` 家族 | `maxTokensLimit`（每种 relay 格式各自校验） |
| 分辨率 / 质量 | 对应倍率表的允许档位 |

**校验绕过路径也要防**：透传字段（如 `Extra["parameters"]`）、任务 `metadata`、multipart 表单字段都能绕过标准 DTO 校验，任何从这些路径读乘数的适配器必须**在本地强制同一上界**。

### 5.3 预扣与结算都安全

```
请求开始 → 按表达式预估 → 预扣额度
请求结束 → 按上游真实用量结算 → 多退（少补）
```

两端都必须安全：

- 超大配额必须**预扣失败并报"额度不足"**，绝不静默回绕
- 结算同样不允许因算术溢出产生负数（等于白送额度）
- 单请求额度限定在 int32 边界，保证批量累加不会逼近 64 位回绕

### 5.4 截断可审计

发生饱和截断时：

1. 写入消费日志的 `other.admin_info.quota_saturation`
2. 产生请求关联的告警日志
3. 管理台可见，用户侧自动脱敏（`admin_info` 对非管理员剥离）

嵌套在 `admin_info` 下意味着**管理端自动可见、普通用户自动不可见**，无需额外配置。

### 5.5 倍率受控

倍率映射走受控入口，拒绝**负数、`0`**、NaN 与 +Inf；非法倍率会被**静默丢弃**（按不生效处理，而非置为免费）。不直接写倍率表字段。

### 5.6 无符号字段要有上界

解析为无符号类型（`*uint`）的字段能接受极大的正数 JSON 值（如 `18446744073686646784`，实际是回绕的负数）。仅 `>= 0` 检查不够，**必须有上界**。

## 6. 预扣策略

| 配置 | 说明 |
| --- | --- |
| `enable_free_model_pre_consume` | 是否对免费模型也做预扣（默认开启） |
| `trust_quota_usd` | 免预扣门槛，默认 10 美元：仅当**令牌侧与钱包余额都满足条件**时跳过预扣——有限额度令牌需**严格大于**该阈值，无限额度令牌直接视为满足；钱包余额同样需严格大于。设为 `0` 关闭该旁路（后台保存会拒绝负数 / NaN / Inf；运行期配置为这些值时同样按关闭处理）；异步任务（强制预扣）与订阅计费**永不豁免** |
| `pre_consume_multiplier` | 预计输入费用的预扣倍率，默认 1；只影响预留不影响实收 |

预扣倍率必须为有限正数，保存与运行时都会校验。

## 7. 上游用量口径归一

不同上游返回的 usage 结构不同，系统在计费前统一归一：

| 差异 | 处理 |
| --- | --- |
| OpenAI 格式 `prompt_tokens` 含缓存 | 归一后 `p` 只含未缓存部分，缓存部分计入 `cr` |
| Claude 格式 `input_tokens` 不含缓存 | 缓存读取与创建分别计入 `cr` / `cc` / `cc1h` |
| 图片 / 音频分项 | 归一到 `img` / `img_cr` / `ai` / `ao` |
| 工具调用次数 | Responses 协议的内置工具调用可附加计费 |

**工具调用附加费**：Responses 等协议的内置工具调用次数按次计费；附加费在计算时已乘分组倍率，并在主体费用（含图片/音频/分辨率等其他倍率）算完之后相加，因此**只受分组倍率影响**。

## 8. 上游用量计数防护

上游返回的用量字段可能不可信（例如供应商声称的时长异常大）。防护措施：

| 风险 | 防护 |
| --- | --- |
| 上游声称的音频时长异常 | 转换时做饱和处理，不直接采信 |
| 上游返回的张数与实际负载不符 | 以实际负载为准计数，或保留请求时预扣的数量 |
| 客户端中断导致计费不足 | 客户端中断不降低计费量，已产生的上游消耗照常结算 |

## 10. 边界与注意事项

| 事项 | 说明 |
| --- | --- |
| 表达式非免费模型 | 免费模型是否预扣由配置决定，默认预扣 |
| 两种模式不混用 | 表达式计费的模型不再读倍率表 |
| 工具调用费只受分组倍率影响 | 附加费在计算时已乘分组倍率，并在主体费用的其他倍率（图片/音频/分辨率等）算完之后相加，因此不随其他倍率放大 |
| 长上下文阶梯是全量 | 超过阈值后**整个请求**按长上下文档位计价 |
| 充值金额精度 | 钱包值限制在 2^53 − 1，保证前端数值精度 |
| 供应商变更定价 | 需更新内置表达式或后台覆盖，不会自动跟随上游 |
