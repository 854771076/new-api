# 08 · 部署与运维

> [← 返回目录](README.md)

---

## 1. 定位

New API 是一个可自托管的服务。部署形态从单机到多节点可选，存储从 SQLite 到 PostgreSQL 均可，缓存可选 Redis。

本章覆盖**怎么部署、怎么配、怎么升级、怎么排障**。

---

## 2. 部署形态

### 2.1 Docker Compose（推荐）

仓库的 `docker-compose.yml` 默认启动 **New API + PostgreSQL**。

> **Redis 默认不启动**：compose 文件里的 `redis` 服务带 `profiles: ["disabled"]`，`new-api` 只依赖 `postgres`。需要 Redis 时：
> - 单节点 Redis → 使用独立栈 `docker compose -f docker-compose.single.yml up -d`（该文件自带 postgres / redis / new-api 定义，**不与基础 compose 叠加**）
> - Sentinel 高可用 → `docker compose -f docker-compose.sentinel.yml up -d`
>
> 基础 compose 仍会注入 `REDIS_CONN_STRING` 指向 `redis` 服务。若不启用 Redis，请移除或覆盖该变量——否则网关会持续尝试连接不可达的 Redis，并发限流将走 fail-open 降级。
>
> compose 文件中同时包含 MySQL 与独立 ClickHouse 日志库的注释示例。

```bash
git clone https://github.com/QuantumNous/new-api.git
cd new-api
```

**启动前必须修改**：

| 项 | 要求 |
| --- | --- |
| 数据库密码 | 在服务定义与连接串中**两处**都要替换示例密码 |
| Redis 密码 | 启用 Redis 时同样要替换 `REDIS_CONN_STRING` 中的示例密码 |
| `SESSION_SECRET` | 设为持久化的随机值，生成方式：`openssl rand -hex 32` |
| HTTPS 控制台 | 配 `SESSION_COOKIE_SECURE=true` 与 `SESSION_COOKIE_TRUSTED_URL`（填精确的公开 HTTPS origin） |

```bash
docker compose up -d
docker compose logs -f new-api
```

### 2.2 全部部署文件

| 文件 | 用途 |
| --- | --- |
| `docker-compose.yml` | 默认：New API + PostgreSQL（`redis` 服务被 `profiles: ["disabled"]` 禁用，不随默认启动） |
| `docker-compose.single.yml` | 独立栈：自带 postgres / redis / new-api 定义，单节点 Redis 拓扑 |
| `docker-compose.sentinel.yml` | 独立栈：Redis Sentinel 高可用拓扑（3 哨兵 + 1 主 2 从） |
| `docker-compose.dev.yml` | 开发环境 |
| `docker-compose.soakenv.yml` | 压测环境 |
| `Dockerfile` | 生产镜像 |
| `Dockerfile.sentinel` | Sentinel 拓扑镜像 |
| `Dockerfile.dev` | 开发镜像 |
| `new-api.service` | systemd 部署单元 |

容器平台支持 **Linux amd64 / arm64**。

### 2.3 源码部署

后端用 Go + Gin，控制台用 React 19 + TypeScript + Rsbuild + TanStack + Tailwind CSS 4。前端依赖与脚本用 **Bun**。

后端会内嵌 `web/dist`，所以必须**先构建前端再启动后端**：

```bash
# 仓库根目录
cd web
bun install --frozen-lockfile
bun run build
cd ..
go run .
```

开发时另开终端跑前端开发服务器：

```bash
cd web
bun run dev -- --port 5173
```

打开 http://localhost:5173 ，开发服务器把 API 请求代理到后端 3000 端口。

容器化开发后端见 `docker-compose.dev.yml` 与 `makefile` 的 `make dev` 目标。

### 2.4 桌面端

`electron/` 提供桌面封装与打包。托盘运行，适合个人开发者本机使用。

## 3. 存储选型

### 3.1 主数据库

| 选项 | 最低版本 | 说明 |
| --- | --- | --- |
| SQLite | — | 免安装，适合单机与试用。**不设 `SQL_DSN` 即用 SQLite** |
| MySQL | ≥ 5.7.8 | 团队部署常用 |
| PostgreSQL | ≥ 9.6 | Compose 默认配置 |

同一套代码三库通用。任何影响数据库行为的改动都必须在三种真实实例上验证；schema 与迁移类改动还需在**全新库**与**由旧版本升级的库**上各跑两遍启动，证明幂等。

### 3.2 日志数据库

| 配置 | 说明 |
| --- | --- |
| `LOG_SQL_DSN` | 独立日志库连接串；不设则与主库同库 |
| ClickHouse | 日志库额外支持，适合高吞吐消费日志 |

把日志库与主库分离的好处：日志写入与业务查询互不影响，且可单独选型（ClickHouse 的批量写入与聚合查询明显更适合日志场景）。

### 3.3 缓存

| 组件 | 说明 |
| --- | --- |
| Redis | 可选。启用后承担限流、并发计数、亲和缓存、令牌缓存等 |
| 内存缓存 | 需显式设置 `MEMORY_CACHE_ENABLED=true` 启用（**默认关闭**）。关闭时渠道/定价等直接读数据库。它是数据库读取的优化项，**不能替代 Redis 的限流与并发共享语义** |

**多节点部署必须共享 Redis**。不同 Redis 实例或纯内存限流器会**各自独立计数**，导致实际并发是节点数的倍数。

## 4. 环境变量

### 4.1 核心变量

| 变量 | 用途 |
| --- | --- |
| `SQL_DSN` | 主数据库连接；不设则使用 SQLite |
| `SQLITE_PATH` | SQLite 文件路径 |
| `LOG_SQL_DSN` | 可选的独立日志数据库连接 |
| `REDIS_CONN_STRING` | Redis 连接串 |
| `SESSION_SECRET` | 持久化认证密钥，**所有节点必须相同** |
| `CRYPTO_SECRET` | 默认继承 `SESSION_SECRET`；共享 Redis 的节点必须使用相同的有效值 |
| `PORT` | 服务端口 |

### 4.2 安全相关变量

| 变量 | 用途 |
| --- | --- |
| `SESSION_COOKIE_SECURE` | 设为 `true` 启用 Secure 刷新 Cookie 与严格的刷新/登出来源校验 |
| `SESSION_COOKIE_TRUSTED_URL` | Secure 模式下必填：逗号分隔的精确 HTTPS origin，不带路径与通配符；本地 HTTP 场景留空 |
| `TRUSTED_PROXIES` | 受信任的反向代理 IP/CIDR，或 `none`；**必须按实际网络显式配置** |
| `PASSWORD_LOGIN_ENCRYPTION_ENABLED` | 登录密码传输加密 |
| `ACCOUNT_PASSWORD_HASH_ALGORITHM` | 密码哈希算法 |

### 4.3 可靠性与超时

| 变量 | 用途 |
| --- | --- |
| `RELAY_TIMEOUT` | 上游调用总超时 |
| `RELAY_IDLE_CONN_TIMEOUT` | 空闲连接超时 |
| `RELAY_RESPONSE_HEADER_TIMEOUT` | 等待上游响应头的超时 |
| `STREAMING_TIMEOUT` | 流式响应超时 |
| `SQL_MAX_OPEN_CONNS` / `SQL_MAX_IDLE_CONNS` / `SQL_MAX_LIFETIME` | 数据库连接池 |
| `SQL_SLOW_THRESHOLD_MS` | 慢查询阈值 |
| `REDIS_POOL_SIZE` | Redis 连接池大小 |

### 4.4 Redis Sentinel

| 变量 | 用途 |
| --- | --- |
| `REDIS_SENTINEL_MODE` | 开启 Sentinel 模式 |
| `REDIS_SENTINEL_ADDRS` | 哨兵地址列表 |
| `REDIS_SENTINEL_MASTER_NAME` | 主节点名，默认 `mymaster` |
| `REDIS_SENTINEL_PASSWORD` | **哨兵节点自身**的认证密码（哨兵 ACL），不是数据节点密码 |
| `REDIS_PASSWORD` | Sentinel 数据节点（master / replica）密码；Sentinel 模式下必需 |
| `REDIS_CONCURRENCY_LEASE_TTL_SECONDS` | 并发租约 TTL |
| `REDIS_CONCURRENCY_BREAKER_COOLDOWN_SECONDS` | 熔断冷却时间 |

### 4.5 功能开关与调优

| 变量 | 用途 |
| --- | --- |
| `DEBUG` | 调试模式 |
| `ERROR_LOG_ENABLED` | 错误日志开关 |
| `MEMORY_CACHE_ENABLED` | 内存缓存开关 |
| `BATCH_UPDATE_ENABLED` / `BATCH_UPDATE_INTERVAL` | 批量更新（用量等）的攒批写入 |
| `CHANNEL_UPDATE_FREQUENCY` | 渠道缓存刷新频率 |
| `SYNC_FREQUENCY` | 各类同步任务频率 |
| `ENABLE_PPROF` | 性能剖析端点 |
| `FRONTEND_BASE_URL` | 前端资源的基础 URL |
| `TASK_POLL_MAX_FAILURES` | 任务轮询最大失败次数 |
| `GEMINI_VISION_MAX_IMAGE_NUM` | Gemini 视觉最大图片数 |

### 4.6 第三方集成

| 变量 | 用途 |
| --- | --- |
| `PYROSCOPE_URL` / `PYROSCOPE_APP_NAME` / `PYROSCOPE_BASIC_AUTH_USER` / `PYROSCOPE_BASIC_AUTH_PASSWORD` / `PYROSCOPE_BLOCK_RATE` / `PYROSCOPE_MUTEX_RATE` | Pyroscope 性能剖析集成 |
| `LINUX_DO_TOKEN_ENDPOINT` / `LINUX_DO_USER_ENDPOINT` | LINUX DO 登录端点 |
| `COHERE_SAFETY_SETTING` | Cohere 安全设置 |

> **跨域策略不可配置**：`middleware/cors.go` 将 `AllowAllOrigins` 与 `AllowCredentials` 固定为 `true`，不受任何环境变量控制。需要收紧跨域时应在反向代理层处理。

### 4.7 配置注入注意

> **仅复制 `.env.example` 不会把变量注入容器。** 必须在 Compose 的 `environment` 或 `env_file` 中显式配置。

## 5. 生产部署检查清单

| 项 | 要求 |
| --- | --- |
| HTTPS | 控制台置于 HTTPS 之后，反向代理需支持**流式转发与 WebSocket 升级** |
| 密钥 | `SESSION_SECRET` 与 `CRYPTO_SECRET` 为持久化随机值，全节点一致 |
| 代理信任 | `TRUSTED_PROXIES` 按实际网络显式配置 |
| 备份 | 持久化并备份数据库与挂载数据 |
| 版本 | 从 Releases **固定版本号**，不跟随 `latest` |
| 多节点 | 共享主数据库与认证密钥，共享同一 Redis |

## 6. 升级

| 步骤 | 说明 |
| --- | --- |
| 1. 读发布说明 | 评估迁移与兼容性影响 |
| 2. 备份 | 数据库与数据目录 |
| 3. 固定版本 | 从 Releases 选定版本 tag |
| 4. 替换镜像 | 滚动替换 |
| 5. 验证 | 检查状态接口与控制台 |

**`latest` 标签会随发布变化**，升级前必须评估迁移与兼容性，不能盲目跟随。

迁移在启动时自动执行，且设计为幂等——但仍建议先在预演环境验证。

## 7. 多节点部署

### 7.1 必须共享的

| 资源 | 不共享的后果 |
| --- | --- |
| 主数据库 | 数据割裂 |
| `SESSION_SECRET` / `CRYPTO_SECRET` | 会话与加密不一致，登录态异常 |
| Redis | **限流与并发计数按节点独立计算**，实际并发是节点数倍 |

### 7.2 可选的

| 资源 | 说明 |
| --- | --- |
| 日志数据库 | 建议共享，否则日志分散在各节点 |
| 静态资源 | 无状态资源，各节点独立 |

### 7.3 会话传播

会话在各拓扑下的传播行为不同，认证与会话指南（`docs/authentication.md`）对此有完整说明。

### 7.4 可用性边界

网关的可用性设计是**单写 + Redis Sentinel 主备**，不是多活：

| 能力 | 状态 |
| --- | --- |
| Redis Sentinel 自动选主 | ✅ 支持（见 [4.4](#44-redis-sentinel)） |
| 主从切换 | ✅ 实测约 6 秒自动提升 |
| **active-active 多活** | ❌ **不支持**——Sentinel 是主备模型，同一时刻只有一个主节点承担写入 |
| **按租户 / 用户分片** | ❌ **不支持**——当前架构无分片键概念 |
| **Redis Cluster** | ❌ **不支持**——已明确排除 |

需要多活或分片时，应在网关之外做入口层拆分，而不是依赖本产品内部实现。

## 9. 排障速查

| 现象 | 排查方向 |
| --- | --- |
| 启动即退出 | `SESSION_SECRET` 是否被设为模板默认值 `random_string`（未设置时会退化为进程内随机 UUID，服务可启动但重启或多节点时会话失效）；`SESSION_COOKIE_SECURE=true` 时是否配置了合法的 `SESSION_COOKIE_TRUSTED_URL`（反之，Secure 未开启却设置了 TRUSTED_URL 同样会致命退出）；数据库是否可达 |
| 控制台空白 | 前端是否构建成功；`web/dist` 是否存在 |
| 流式响应被截断 | 反向代理是否关闭了缓冲；是否配置了流式超时 |
| WebSocket 连接失败 | 代理是否支持 WebSocket 升级 |
| 多节点限流失效 | 是否共享了同一个 Redis |
| 会话频繁失效 | 各节点 `SESSION_SECRET` 是否一致；反向代理是否传递了正确的 Host |
| 密码登录失败 | 凭据是否正确；`PASSWORD_LOGIN_ENCRYPTION_ENABLED` 是否前后端一致；滚动升级期间 `ACCOUNT_PASSWORD_HASH_ALGORITHM` 是否与已有哈希兼容 |
| 数据库迁移报错 | 是否为受支持的版本；备份是否可恢复 |
| 上游 429 频发 | 渠道并发上限、权重分配与上游配额是否匹配 |
