# 04 · 用户与访问控制

> [← 返回目录](README.md)

---

## 1. 定位

访问控制回答三个问题：**谁在调用（身份）**、**能调什么（授权）**、**能调多少（额度）**。

New API 的访问控制分五层，从粗到细：

```
用户  ──▶  分组  ──▶  令牌  ──▶  模型白名单  ──▶  额度
 │         │          │
 │         │          └── 可绑定并发上限、IP 限制、有效期
 │         └── 决定可见模型、可用渠道、计费倍率
 └── 角色决定管理面权限
```

---

## 2. 用户

### 2.1 用户属性

| 属性 | 说明 |
| --- | --- |
| 用户名 / 邮箱 | 登录标识 |
| 密码 | 支持加密存储 |
| 角色 | 见 §2.2 |
| 分组 | 见 §3 |
| 额度 | 可用余额，扣减后减少 |
| 邀请码 | 注册时可填写的邀请关系 |
| 状态 | 启用 / 禁用 |
| 签到 | 可启用每日签到领额度 |
| 绑定信息 | 邮箱绑定、第三方账号绑定 |

> **实名验证不在平台能力范围内**——需由部署方在其业务侧完成。

### 2.2 角色体系

角色分两层：**系统角色**（用户属性）与**授权角色**（策略主体）。

#### 内置授权角色

| 角色 | Key | 性质 | 说明 |
| --- | --- | --- | --- |
| Root | `root` | **超级用户** | 拥有全部权限，无需逐条策略 |
| Admin | `admin` | 普通角色 | 按基线授权矩阵授予，可被策略调整 |

角色可自定义扩展，存在 `authz_roles` 表中，支持启用/禁用与排序。

#### 权限判定顺序

```
① 主体解析：用户的授权角色集合（系统角色映射 + 自定义角色）
        ↓
② 超级用户短路：集合含超级用户角色 → 直接允许
        ↓
③ 未知权限：不在权限目录中 → 拒绝
        ↓
④ 用户级覆盖：查该用户的显式策略
        命中 allow → 允许；命中 deny → 拒绝
        ↓
⑤ 角色基线：任一角色的基线策略允许 → 允许
        ↓
⑥ 否则拒绝
```

**关键规则**：显式 `deny` 优先于 `allow`。同一次查询中只要存在 deny 策略，allow 不生效。

### 2.3 权限目录

权限以「资源 → 动作」二维组织。系统维护一份权限目录（catalog），管理台可读取并据此渲染权限矩阵界面：

| 概念 | 含义 |
| --- | --- |
| Resource | 受控对象，如 channel、user、token、log 等 |
| Action | 对该对象的操作，如 read、create、update、delete |
| Role baseline | 角色对该资源各动作的基线许可 |
| User override | 针对单个用户的显式覆盖（只存覆盖项） |

用户级覆盖只存储**差异项**，不复制整张矩阵——这让权限变更的存储与审计成本可控。

## 3. 分组

分组是 New API 里连接「权限」与「计费」的关键概念。

| 分组影响 | 说明 |
| --- | --- |
| **可见模型** | 令牌所属分组决定能调用哪些模型 |
| **可用渠道** | 渠道归属分组，与令牌分组交叉匹配后才是候选 |
| **计费倍率** | 分组倍率乘进最终费用，不同分组可以有不同定价 |
| **自动分组** | 可配置规则自动把用户或请求路由到合适分组 |

分组倍率还有一层 **group-to-group 倍率**：某个用户分组的请求走另一个分组时，可再乘一个系数，实现"内部转移定价"。

## 4. 令牌

### 4.1 两种凭证

| 凭证 | 用途 | 调用入口 |
| --- | --- | --- |
| **API 令牌** | 业务系统调用模型 | `/v1/*` |
| **Personal Access Token** | 用户管理自身账户（脚本化管理台资源） | `/api/*` |

### 4.2 令牌属性

| 属性 | 说明 |
| --- | --- |
| 名称 / 备注 | 标识用途 |
| 密钥 | 唯一凭证，调用时以 `Bearer sk-...` 携带 |
| 分组 | 决定可见模型、可用渠道与计费倍率 |
| 额度 | 无限额度或指定额度（令牌本身**无周期重置**；周期发放属于订阅计划能力） |
| 已用额度 | 累计消耗 |
| 模型限制 | 白名单，空表示不限制 |
| 过期时间 | 到期后失效 |
| 状态 | 启用 / 禁用 |
| IP 限制 | 限定来源 IP |
| 并发上限 | 见 §4.3 |

> 令牌之间**没有父子层级**，不能创建子令牌；令牌统一归属于某个用户。

### 4.3 并发上限

令牌级并发上限可分档配置：

- 全局限：对该令牌所有模型统一生效
- 按模型 CSV：不同模型不同上限，格式为 `模型名=上限`，多个模型用逗号分隔（如 `gpt-4o=3,claude-sonnet=2`）

写入前会做解析预览与格式校验，格式非法的配置直接拒绝保存。

> 并发上限配置为**管理员专属**。服务端在更新白名单、读取过滤、响应体字段裁剪三处同时强制——非管理员的令牌响应体中不包含并发相关字段。

### 4.4 令牌可见性

令牌读取按**当前登录用户**过滤：管理员同样只能读取**自己**的令牌，他人令牌一律不可见。管理员与普通用户的差别在于响应中是否包含并发上限等字段。

| 调用者 | 可见内容 |
| --- | --- |
| 管理员查看本人令牌 | 全部字段，含并发上限、模型限制、IP 限制 |
| 普通用户查看本人令牌 | 自己的令牌信息，敏感字段按规则裁剪（不含并发字段） |
| 他人令牌 | 不可见 |

## 5. 认证方式

### 5.1 支持的凭证类型

| 方式 | 适用 | 说明 |
| --- | --- | --- |
| **密码** | 通用 | 密码加密存储 |
| **邮箱验证** | 注册与找回 | 需邮箱服务配置 |
| **TOTP 双因素** | 登录二次校验 | 用户可自行注册与启停，无全局强制开关 |
| **WebAuthn / Passkey** | 抗钓鱼强认证 | 依赖 HTTPS 与域名配置 |
| **OAuth / OIDC** | 企业单点登录 | 内置多个常用提供方，且支持自定义 OAuth 提供方 |
| **第三方账号绑定** | 微信、Telegram 等 | 可绑定与解绑 |

### 5.2 登录会话管理

- 用户可查看自己当前的登录会话列表
- 可主动注销指定会话
- 会话受服务端校验，注销后立即失效

### 5.3 自定义 OAuth 提供方

除内置提供方外，管理员可配置自定义 OAuth / OIDC 提供方，接入企业自有身份系统。

### 5.4 限流与防护

| 措施 | 说明 |
| --- | --- |
| 关键操作限流 | 登录、注册、密码重置、邮箱验证、OAuth 回调等按类型分级限流 |
| Turnstile 人机校验 | 关键入口可开启 |
| 匿名请求体上限 | 限制未认证请求的体积 |
| 验证码防重放 | 邮箱验证码、登录验证码独立校验 |

## 6. 额度与充值

### 6.1 额度模型

额度是**用户级**的余额，令牌级额度是用户额度的子集。

| 概念 | 说明 |
| --- | --- |
| 用户额度 | 用户总余额，所有令牌共享 |
| 令牌额度 | 单个令牌的独立可用上限；实际可用额度同时受用户余额约束（用户余额耗尽即拒绝） |
| 预扣 | 请求开始前按预估扣减，余额不足直接拒绝 |
| 结算 | 请求结束后按真实用量结算，差额退回 |
| 额度调整 | 管理员可增减或覆盖用户额度，变更进审计日志 |

### 6.2 充值途径

| 途径 | 说明 |
| --- | --- |
| 管理员手动调整 | 后台直接加减额度 |
| 兑换码 | 批量生成，redeem 兑换 |
| 订阅 | 周期性额度包 |
| 支付网关 | Stripe、Creem、Waffo、易支付（epay）等回调 |
| 钱包 | 用户钱包余额 |

充值金额的换算走受控函数，限制在 JavaScript 安全整数范围内（2^53 − 1），避免前端数值精度问题。

### 6.3 订阅

订阅是绑定到**用户**的周期性额度包（不支持绑定到令牌）：

| 属性 | 说明 |
| --- | --- |
| 额度 | 每周期发放的额度 |
| 周期 | 发放频率与时长 |
| 绑定对象 | 用户 |
| 状态 | 生效中（`active`）/ 已过期（`expired`）/ 已取消（`cancelled`） |

额度耗尽后订阅本身仍为 `active`；是否回退到钱包扣费取决于用户的**计费偏好**（`billing_preference`）：`subscription_first`（默认）下仅在订阅允许钱包溢出（`allow_wallet_overflow`）时才回退；`subscription_only` 不回退，直接报订阅额度不足。

### 6.4 兑换码

| 属性 | 说明 |
| --- | --- |
| 额度 | 面额 |
| 状态 | 未使用 / 已使用 / 已禁用 |
| 有效期 | 可选过期时间 |
| 记录 | 记录兑换人（`UsedUserId`）与兑换时间 |

> 当前**不支持定向发放**——兑换码不绑定特定用户或分组。

## 7. 审计

所有管理写操作进审计日志：

| 记录内容 | 说明 |
| --- | --- |
| 操作者 | 管理员身份与角色 |
| 动作 | 如 `channel.delete`、`user.quota_add` |
| 目标 | 被操作对象的 ID 与关键字段 |
| 请求信息 | 方法、路由、状态码、是否成功 |
| 来源 | 客户端 IP |
| 时间 | 操作时间 |

审计记录包含用户额度调整的前后值，便于财务核对。

**敏感信息排除**：审计与认证事件不记录密码、验证码、恢复码、私钥与可用的会话或认证令牌。

---

## 8. 边界与注意事项

| 事项 | 说明 |
| --- | --- |
| 显式 deny 优先 | 想"收回"某个权限，必须显式 deny，光删 allow 不够 |
| 分组交叉匹配 | 令牌分组与渠道分组需匹配才可用，配置错会导致"模型不可用" |
| 用户额度是总闸 | 令牌额度再高，用户额度耗尽也无法调用 |
| 兑换码一次性 | 兑换后立即失效，重复兑换被拒 |
| 角色与权限是两件事 | 系统角色决定"能进哪个界面"，授权角色决定"能点哪个按钮" |
