## B. Supabase 与托管 Key（01、03、12）

- [ ] B01 用户只登录 Supabase 即可查余额、调用 AI 和发起充值，无 new-api OAuth 跳转。
- [x] B02 身份验证拒绝伪造、过期和其他项目的凭据；目标用户从可信映射解析。
- [ ] B03 01 的受控代理开户事务原子写入账户/来源/App/唯一外部身份，返回稳定 ID；同元组并发唯一、响应丢失/映射写失败可恢复，冲突与越权拒绝、不复活停用账户；不复制 OAuth 映射，不以普通 CreateUser 冒充。
- [x] B04 PAT、个人 Key、高权限 Supabase 密钥均不出现在浏览器、可读 metadata、公开响应或日志。
- [x] B05 管理员按明确 role/scope 创建、更新、停用、轮换指定用户的 App Key；原 self 接口不可越权。
- [x] B06 代理 App Key 只扣指定 App 的余额，不选择或回退 App/平台订阅；余额不足即拒绝，其他用户、App 与平台资金不受影响，Key 限额独立生效。
- [ ] B07 模型/IP/组限制、App 白名单、App 停用、Key 撤销及缓存失效生效。
- [ ] B08 同步、流式与异步任务的预扣、差额、失败退款及任务读取隔离均归属同一 App。
- [ ] B09 平台旧 Key 和 OAuth 旧路径回归通过。
- [ ] B10 正常轮换按创建、保存、验证、切换、撤销执行；响应丢失/保存失败/并发可恢复，旧 Key 不提前撤销，紧急撤销独立立即生效；轮换共享原预算及在途预留/结算/退款，上限100已用90仍余10，旧新并发不能超额，不能复制计数或重复退款；缺预算连续性时拒绝受限轮换。
- [x] B11 Key 周期/窗口规则仅限制消费，不表示订阅或充值；绑定验证目标用户所有权，不能误用 PAT 持有人的规则或静默跳过限制。不把独立未提交开发当成已发布合同，不重复开发规则引擎。

## C. 指定用户收银台（02、09、10）

- [ ] C01 管理员 PAT 为指定用户、显式平台或 App 创建订单，返回可用收银台链接。
- [x] C02 普通 PAT、scope 不足、失效 PAT、无效目标和非法范围被拒绝；停用拒绝新下单，但允许授权读取/对账已有订单。
- [x] C03 服务端确定用户价格组、金额、货币和到账 quota；负数、越界和客户端篡改失败。
- [x] C04 同幂等键同参数返回原订单；不同参数冲突；网络超时能查订单恢复。
- [x] C05 订单快照原子固定用户、来源、App、购买目标、货币、金额、到账 quota 与比例；未配置比例显式 null，旧无快照订单不套当前比例，切换不改归属。
- [x] C06 webhook 错签名、金额/货币不符与非法状态不入账；重复成功通知仅入账一次。
- [x] C07 浏览器回跳和余额变化不作为支付成功证明；订单查询只能看到授权目标。
- [x] C08 付款方式按已支持矩阵展示；未配置/不支持时明确失败，不退回平台钱包。
- [x] C09 代理可查询本人充值/一次性商品订单，不能购买或授予订阅；OAuth 订阅结果仍按其本人来源与范围查询。
- [x] C10 停用前有效订单继续按原快照处理真实付款并可查账；过期后真实付款有可审计异常处理，不静默丢款或恢复调用权限。
- [x] C11 10 交付 OAuth api:read 本人固定 App 的订单列表/详情/状态查询并接通 OAuth 参考 BFF，覆盖充值/商品/订阅；无 PAT/控制台会话仍能确认订单，跨用户/跨 App、错 scope、失效 token 拒绝，关闭 OAuth 后走控制台历史只读入口。
- [x] C12 10 补齐订单查询覆盖的全部 checkout 稳定 order_id（含余额充值/订阅及 Stripe/Epay），保留旧字段与 success/pending；余额变更和可查订单同事务。BFF/类型/schema 保存可信关联及调用前请求键；两笔同套餐不同键可分别查询，同键并发/丢响应恢复原 ID 且不重复扣款/授予/建单，改参数冲突，禁止按最新订单/URL/金额猜测；旧实例缺 ID 保持待确认；旧客户端缺键兼容但未知结果不自动重下单。

## D. 积分与 quote（04、05、06）

- [x] D01 管理员能配置每 App 的 quota_per_credit，旧 App 未配置时保持原显示。
- [x] D02 0、负数、小数及超上限比例被拒绝，修改比例显示已有余额单位变化提示。
- [x] D03 同样 100000 quota，比例 1000 得 100 积分，比例 100 得 1000 积分。
- [x] D04 独立规范化钱包返回所选 app_id 的 quota/用量/积分/比例，平台比例和积分为 null；会话、管理员 PAT、待开发 token 固定 App 的 OAuth 入口返回同一 DTO。App1000/已用200/比例100返回10积分及已用2，旧 OAuth 平台quota9000/App1000字段不变；积分为十进制字符串，最多6位向零截断（正数等同向下截断）。
- [ ] D05 正消耗低于显示精度时界面提示小于最小单位；无限额不显示成零额度。
- [x] D06 quota=1000、used_quota=200 时显示余额 1000 quota 对应积分，不错误显示 800。
- [x] D07 定价/PAT 读取与原 OAuth 读取兼容；quote 返回 estimated_credits，不把估算标为实际结算。
- [x] D08 提交前价格/比例变化触发更新报价确认；已有订单按原快照解释，账本不受比例修改影响。
- [x] D09 修改比例不改变 quota、模型价格、支付金额、实际扣费或退款。
- [x] D10 旧 quote.credits 保持原始 quota 的数值语义并弃用，新 estimated_credits 为 string|null；StudioClient 与类型迁移，新旧客户端分别验证。
- [x] D11 报价确认绑定服务端版本/摘要、用户、来源、App 及输入；变化重新确认，代理估算不混入订阅权益。
- [ ] D12 负 quota 表示欠费，-100/比例100返回 "-1"，-1/3返回 "-0.333333"；极小负值积分 "0" 仍显示微量欠费，真实零独立；充值先抵欠费，不改账本或丢弃实际补扣，新调用余额不足拒绝。
