# 11: 后台用户、额度调整、套餐、商品和订单统一 App 范围

**What to build:** 管理员切换顶部 App 后，相关管理页以同一 App 的积分与额度语义展示、筛选和操作，不出现列表看 A、详情或写入操作 B 的情况。

**Blocked by:** 01 — 创建 App 选择双接入模式，并按开关显示配置与切换选项；05 — 按用户与 App 返回统一余额、积分及可信统计

**Status:** local implementation — 已实现；本地验证与剩余验收见下文，未发布tracker

- [x] 后台用户列表区分“资金视角”和“账户归属”：现有 app_id LEFT JOIN 只是为全体用户附加该 App 余额，不是归属过滤。11 增加代理账户的服务端归属条件；所选 App=A 时，无论是否指定来源筛选，代理行只包含 owner_app_id=A，列表/搜索/总数/分页/排序使用相同条件；无钱包记录的 A 代理用户仍返回零余额，不能按钱包是否存在过滤。OAuth/平台旧账户保留原有资金视角，不把它们改成单 App 账户；全局管理员用户目录可查看所有代理用户并标注归属，但不能据此向其他 App 或平台写入其资产。
- [x] 确定性夹具：A 有已建钱包与未建钱包两名代理用户，B 有一名代理用户，另有旧 OAuth/平台用户。A 的代理筛选只返回前两人且 total=2，搜索/分页/排序结果一致；未加来源过滤时也不混入 B 代理行。兼容旧 OAuth/平台资金视角与全局管理员目录。
- [x] 后台有独立于顶部/钱包的 App 范围筛选，包含仅托管 Key、仅授权登录和双模式 App；OAuth 关闭的产品仍可查询与管理。App 管理可按接入模式过滤，Key 管理由对应切片提供 App/用户/状态过滤。
