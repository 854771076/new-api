# 11: 后台用户、额度调整、套餐、商品和订单统一 App 范围

**What to build:** 管理员切换顶部 App 后，相关管理页以同一 App 的积分与额度语义展示、筛选和操作，不出现列表看 A、详情或写入操作 B 的情况。

**Blocked by:** 01 — 创建 App 选择双接入模式，并按开关显示配置与切换选项；05 — 按用户与 App 返回统一余额、积分及可信统计

**Status:** draft — 待确认拆分及 tracker 后，以 ready-for-agent 发布

- [ ] 复用现有用户列表 app_id 筛选、搜索、排序和额度调整能力，补齐积分展示与范围确认，不重新实现已有功能。
- [ ] 后台有独立于顶部/钱包的 App 范围筛选，包含仅托管 Key、仅授权登录和双模式 App；OAuth 关闭的产品仍可查询与管理。App 管理可按接入模式过滤，Key 管理由对应切片提供 App/用户/状态过滤。
- [ ] 另外按用户身份来源 proxy/oauth 筛选和标记，不能从 App 双模式开关推断来源；代理用户无订阅查看/授予/购买操作，服务端同样拒绝，不影响历史 OAuth 用户订阅审计。一次性额度商品与订阅套餐明确区分。
- [ ] 用户详情、批量入口和额度调整使用目标 App 同一合同；管理员看到 quota 与对应积分，最终按安全 quota 执行，保留既有权限证明/角色约束。
- [ ] 套餐、商品、订单在列表、详情、编辑、创建、补单及失效操作均校验真实归属；修改范围不可通过缺省 app_id 意外迁回平台。
- [ ] 查询键、抽屉和确认弹窗固定用户/App，切换关闭未提交编辑；已完成订单不被当前选择重标归属。
- [ ] 服务器端授权与范围检查不依赖前端隐藏按钮；无权限、跨 App、错 user_id、非法额度及停用目标行为明确。
- [ ] 对已存在页面采用功能行为测试证明筛选、排序、编辑与金额不串范围，不增加一套通用状态系统或重复确认组件。
- [ ] 真实三数据库验证查询、排序、余额加减/覆盖及约束；新 schema 才做对应升级矩阵，记录实际命令与结果。
- [ ] 七语言、数字精度、键盘与移动布局、类型检查、lint、适用构建及基线审计通过。

验收证据对应 checklist F09、F10。这里以补齐现有范围合同为界，不扩展整个后台管理产品。
