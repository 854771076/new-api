# 03: 后端管理指定用户的 App Key，并从对应 App 资金来源扣费

**What to build:** 管理员可为独立代理用户创建与 App 绑定的个人 AI Key，进行限制修改、停用和轮换。用户由 App 后端使用该 Key 调用 AI，只消耗对应 App 钱包余额；代理模式不支持订阅，不需要 OAuth 用户令牌。

**Blocked by:** 01 — 创建 App 选择双接入模式，并按开关显示配置与切换选项

**Status:** draft — 待确认拆分及 tracker 后，以 ready-for-agent 发布

- [ ] Key 持久化不可由请求改写的 app_id，0 保持平台旧行为；管理员管理响应显示目标 user_id 与 App 归属。
- [ ] App 后端创建时使用自身配置的 app_id；后台人工创建从可管理且启用托管模式的 App 中选择。同一自然人在不同 App 分别使用独立代理 new-api user_id 与 Key，代理账户的 App 归属不可变，不能给该账户创建其他 App 的 Key；原有 OAuth/平台账户行为不变，Key 创建后归属不可修改。
- [ ] 管理列表支持 App、目标用户、Key 状态筛选，脱敏显示归属；托管模式关闭后拒绝该模式新调用，OAuth 模式不受影响，后台结算不被阻断。
- [ ] 指定用户管理接口验证管理员角色、对应 api_key scope 和目标；保留本人 self 接口边界。创建/轮换的新秘密仅返回给授权后端，列表始终脱敏。
- [ ] App Key 在 relay 中建立 App 资金上下文，复用既有预扣、差额结算、退款，但显式选择余额资金来源；不选择或回退 App/平台订阅，不回退平台钱包。余额不足即拒绝，异常残留订阅不能参与抵扣。
- [ ] 保留 Key 的模型、IP、组与限额限制，同时执行 App 模型白名单、停用状态、Key 过期/撤销以及缓存失效。
- [ ] 同步、流式和已支持异步任务均维护用户与 App 归属；后台轮询结算不依赖前端会话，其他 App 不能读取或操作该任务。
- [ ] 正常轮换遵循创建新 Key、安全保存、验证、切换、撤销旧 Key；操作 ID 去重，失败时保留仍有效的旧 Key。新秘密响应丢失时受控恢复或撤销无法恢复的替代 Key 后重试，不要求跨系统原子事务；紧急撤销立即生效。测试保存失败、响应超时、并发和各步中断恢复。
- [ ] 轮换必须让旧/新凭据共享同一逻辑消费预算，保留累计上限、剩余额度、周期已用量及在途预留；换 Key ID 不得重置计数。旧 Key 已受理任务的结算/退款仍归原预算，不能靠一次性复制计数处理并发；未具备预算连续性时明确拒绝受限 Key 轮换，不能静默放宽限制。验收：上限 100、已用 90，轮换后仍只可用 10，旧/新并发合计不超过原上限，重复恢复不重复预留或退款。
- [ ] Key/用户归属校验包含可信身份来源，不能绑定或消耗 OAuth 用户资产；管理端区分来源。截图周期/窗口额度规则仅是消费限制，不是订阅或充值；复用目标实例已验证的 Key 限制，不把工作区独立未提交的规则开发当作已发布合同，不重复开发规则引擎。
- [ ] 若支持额度规则绑定，管理员代理操作验证规则属于目标用户及允许范围，不能绑定 PAT 持有人的 self 规则；跨用户绑定拒绝。规则限制与余额扣费同时生效，不能凭周期重置增加钱包余额，不能静默跳过已绑定限制；不支持的实例明确返回不可用。
- [ ] 管理端可确认 Key 归属，API 客户端可独立演示“充值 A、调用 A、A 减少，平台/B 不变”；平台旧 Key 与 OAuth 旧路径回归通过。
- [ ] 测试从 HTTP/relay 可观察结果断言权限、token 限额、预扣/实扣/退款、余额不足时不消耗订阅及任务幂等；同 App 两来源用户互不影响，OAuth 订阅路径保持可用，不重复跨层堆砌夹具。实施前读取适用 OWASP 指南并记录 ASVS 版本与采用要求。
- [ ] Key schema 与资金路径在真实三数据库验证；迁移覆盖旧 Key app_id=0、已有任务与索引保留及两次启动，相关独立日志库同步验证；完成项目基线审计。

验收证据对应 checklist B04—B11。这是 App 多钱包闭环的必要兼容扩展；复用现有 App 资金上下文，避免重写结算引擎。
