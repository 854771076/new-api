# 04: 管理员配置每个 App 的积分比例，并保留旧 App 显示

**What to build:** 管理员在 App 编辑界面配置 quota_per_credit，保存后管理接口返回该配置及可理解的换算示例；不同 App 可以采用不同积分单位，旧 App 不因升级突然改变余额展示。

**Blocked by:** None (can start immediately)

**Status:** draft — 待确认拆分及 tracker 后，以 ready-for-agent 发布

- [ ] quota_per_credit 明确定义为“1 积分对应的 quota 数”，仅允许正整数且不超过现有安全额度上限；空值表示未启用积分显示。
- [ ] App 创建、详情、列表及编辑契约兼容扩展；管理员表单复用现有组件和校验，错误由服务端再次验证。
- [ ] 拒绝 0、负数、小数及越界输入；未配置的旧 App 保持原额度/货币显示，迁移不改写余额或价格。
- [ ] 保存前展示换算示例及“已有余额显示也会变化”的提示；原始 quota、模型定价、订单金额和订阅额度保持不变。
- [ ] 确定统一换算：十进制字符串，最多 6 位小数且向下截断；低于精度的正值在 UI 明确提示，0 与无限额分别处理。
- [ ] 已有旧订单没有比例快照时显示旧金额/quota，不能用新比例伪造历史购买时的承诺。
- [ ] 表单可用键盘操作、七语言文案完整；按项目格式化工具处理数字，不新增重复的 UI 或 formatter 体系。
- [ ] HTTP 验证两 App 不同比例及旧契约；紧凑数值边界用例覆盖 100000/1000、100000/100、1/3、最小正数及安全上限，不依赖二进制浮点近似。
- [ ] App schema 在真实三数据库完成新建、发布版升级与两次启动检查，记录数据/约束保留；本分支适用测试、前端检查与基线审计通过。

验收证据对应 checklist D01—D03、D05、D09。此票可独立演示配置，不阻塞应用广场。
