# 09: 钱包主区域显示当前 App 的订阅、套餐与商品

**What to build:** new-api/OAuth 用户切换 App 后，在现有钱包主区域查看本人的订阅、剩余套餐额度及可购买套餐/商品，并完成当前 App 的购买。代理用户不支持订阅；本票不移除底部汇总，删除动作留给 13 整体验收。

**Blocked by:** 02 — 管理员 PAT 为指定用户打开收银台并查询支付结果；08 — 普通用户切换 App，并在钱包主区域看到对应积分

**Status:** draft — 待确认拆分及 tracker 后，以 ready-for-agent 发布

- [ ] 本人订阅/套餐/商品读取均验证用户与范围，平台只列平台内容，App 只列对应 App；支持已过期/取消历史，不泄露其他用户。
- [ ] 复用现有订阅和商品卡片，显示总量、已用、剩余、有效期及无限额；钱包余额与到期额度不相加。
- [ ] 积分单位沿用当前 App 比例，套餐价格仍显示真实货币，未配置比例保留旧展示。
- [ ] OAuth 用户订阅沿用控制台本人会话或既有 OAuth 支付核心和支持矩阵，不新增 PAT 代理订阅；一次性商品复用 02 的目标、幂等和快照约束。不凭平台成功路径推断 App 也支持某渠道。
- [ ] 能力按用户来源确定，双模式 App 的代理用户仍不支持订阅；隐藏订阅 UI 并在读取、购买、后台授予和扣费入口拒绝，不从另一来源账户显示权益。
- [ ] 余额购买只使用正确 App 钱包；资金不足、达到限购、错误 App 商品、过期/停用目标及未完成合规确认均明确失败。
- [ ] 完成主区域订阅迁移但保留旧卡；向 13 提供资产覆盖证据，由其在 09/10/12 完成后移除。关闭 OAuth 的历史本人订阅仍可经独立只读资产入口查阅，不要求重新启用授权或重新显示下拉选项。
- [ ] 缺少套餐/订阅时为空状态；支付状态不从浏览器回跳推断，购买中切换不会改写已有订单或重复提交。
- [ ] 扩展已有 App purchase 集成回归与钱包交互测试，验证跨范围拒绝、余额扣款、重复通知和完整迁移；验证三数据库及适用迁移，不把数据检查推到 13。
- [ ] 完成七语言、可访问性、类型检查、lint、适用构建与基线审计。

验收证据对应 checklist C08、C09、F03、F04。02 提供的共享代理订单能力是本票的真实前置，避免复制支付逻辑。
