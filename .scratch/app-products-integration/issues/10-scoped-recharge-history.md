# 10: 当前 App 充值、订单历史与到账状态形成闭环

**What to build:** 用户在所选钱包充值，看到实际支付金额及到账积分，打开该目标的收银台，并从当前范围订单历史确认到账。平台与其他 App 订单不会混在一起。

**Blocked by:** 02 — 管理员 PAT 为指定用户打开收银台并查询支付结果；08 — 普通用户切换 App，并在钱包主区域看到对应积分

**Status:** local implementation — 已实现；本地验证与剩余验收见下文，未发布tracker

- [x] 控制台本人充值从会话确定用户，后台 PAT 模式从可信映射确定用户；共用同一目标校验和支付核心，普通浏览器不接触管理员 PAT。
- [x] 10 交付待开发的 OAuth 本人订单列表/详情/状态查询，api:read，user_id 与 App 均固定来自已验证 token，不能通过订单号或 app_id 参数跨用户/跨 App；覆盖本人 App 充值、一次性商品及订阅订单。返回订单标识、类型、归属及真实支付状态；订阅权益状态不代替订单终态。代理仍不支持订阅，普通 token 不能查询代理账户资产。具体新路由实施时确定，不宣称已有接口；不借 dashboard PAT 或浏览器会话补 OAuth 权限。OAuth 关闭后此入口拒绝，历史查询走已有设计的控制台独立只读入口。
- [x] 同步 OAuth 参考 App/BFF 的订单状态读取到上述 token 查询入口，保留订单与可信用户/App 关联；只持有 OAuth token、没有 PAT/dashboard 会话也能确认付款。未实现实例保持待确认，不能以余额或活跃订阅摘要替代成功。本票负责该 OAuth 分支，12 的代理参考仍不依赖 10。
- [x] 充值档位、金额预览、到账积分和确认弹窗明确钱包名称；App 仅展示已支持且已配置的方式。
- [x] 订单列表、分页、搜索与详情按本人及显式 app_id 过滤；平台范围不混入 App 订单，目标用户查询不泄露他人订单。
- [x] 支付确认固定报价和目标，发起后订单归属不可变；切换清空未提交金额、付款方式和弹窗，原订单仍能按原范围查询。
- [x] 以订单状态确认成功，到账后刷新原目标钱包；返回页面若已选其他 App，不把旧订单的成功消息伪装成当前 App 到账。
- [x] 10 负责补齐上述订单读取所覆盖的全部 checkout 分支（充值、一次性商品、OAuth 订阅及其已支持支付方式），兼容保留旧字段，统一返回稳定 order_id，保留同步 success 与在线 pending 的区别；包括当前缺 ID 的余额充值、余额订阅及 Stripe/Epay 等路径。余额转账/购买须在同一事务内持久化可查询订单、归属和实际资金/权益变更，不能只给响应临时生成 ID。
- [x] 在任何扣款、授予或外部建单副作用前持久化幂等请求，按可信操作者、来源、用户、App、购买类型绑定稳定请求键和规范化输入；同键同参数恢复原 order_id/快照，同键改参数冲突。在途请求返回处理中并按同键恢复，外部结果不明先对账，不再次扣款、授予或建单；过期订单保留原 ID/终态，明确新购才用新键。不能以最新订单、计划/金额、URL 解析或余额变化猜测目标。新参考 BFF 必须提交请求键；兼容旧客户端缺键请求，但不承诺可恢复重试，结果不明时禁止自动重下单。代理订单沿用 02 的合同；本票扩展既有共享 checkout 核心，不要求先完成 09。
- [x] 同步参考 BFF、gateway-contract.ts、响应 schema 和持久化关联：调用前保存稳定请求键，按已验证用户/来源/App/类型保存响应 order_id，丢响应或本地写失败按同键恢复。已确认支持新合同的分支必须返回 ID；旧实例缺 ID 保持待确认。
- [x] 邀请奖励、兑换码和转入平台等未支持 App 的功能在 App 视图隐藏或明确引导切回平台，不后台偷偷改目标。
- [ ] 覆盖支付处理中切换、乱序金额预览、pending/failed/expired/success、重复通知、分页隔离及失败恢复的 HTTP/浏览器回归。
- [x] HTTP/参考 BFF 覆盖 OAuth 充值/商品/订阅各类订单、无 api:read、过期/撤销 token、跨用户/跨 App 订单号及模式关闭；订单成功后才刷新权益，重复查询无写入副作用。
- [ ] 覆盖同用户同 App 同套餐并发两笔独立购买（不同键）返回不同 ID，各自查终态；同键并发/首次响应丢失恢复同一 ID，余额购买/转账仅扣款入账一次且有可查订单，参数冲突拒绝；所有已支持 checkout 支付分支均验证 ID 与归属。
- [ ] 实际支付和钱包查询行为在真实三数据库验证，相关 schema 覆盖迁移；运行适用前端检查和分支基线审计。
