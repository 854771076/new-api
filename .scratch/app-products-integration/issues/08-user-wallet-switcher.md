# 08: 普通用户切换 App，并在钱包主区域看到对应积分

**What to build:** 普通用户获得与管理员一致的顶部 App 选择体验，钱包标题、余额、已用额度及请求统计随选择更新，刷新或切换账号不会展示别人的范围。

**Blocked by:** 01 — 创建 App 选择双接入模式，并按开关显示配置与切换选项；05 — 按用户与 App 返回统一余额、积分及可信统计

**Status:** local implementation — 已实现；本地验证与剩余验收见下文，未发布tracker

- [x] 复用现有选择器与 active App 状态；新增普通用户可读的安全列表，包含平台及本人可信关联的 App，不调用管理员全量配置接口。
- [x] 本人指当前 new-api/OAuth 身份，独立代理用户的资产不出现在此列表；代理用户通过子 App 访问。筛选、缓存及持久化包含可信身份来源，不能因同邮箱或同 App 合并资产。
- [x] 顶部/钱包选项仅包含 oauth_enabled=true 且满足关联/授权条件的 App；关闭 OAuth 即隐藏，即使该 App 仍使用托管 Key。关闭当前选择后回平台，不删除原资产。
- [x] 列表权限独立于广场展示；隐藏 App 的本人已有资产可查，停用 App 显示状态并允许看历史，无权/删除选择回到平台。
- [x] 持久化按账号隔离，退出清理；管理员仍按原可管理范围选择。
- [x] 主卡迁移到 05 的规范化钱包合同；旧 /oauth/userinfo 的平台 quota 不作为 App 余额。钱包标题、主统计卡、积分单位、原始额度及统计窗口同属所选范围；平台显示保留原语义，无法统计显示暂无数据。
- [ ] query key 包含用户与 App，切换取消或忽略旧响应；加载时不能在新标题下短暂显示旧余额。
- [x] 零钱包、真实欠费、微量欠费、请求失败、加载和重试状态可区分，积分不重复减累计用量；负余额保留符号，不能钳制为零。
- [x] 本阶段保留旧资产入口直到 13 验证全部迁移；尚未改造的支付/订阅区域明确标识平台范围，在 App 视图中禁用或隐藏，不能形成误导。OAuth 关闭的历史资产提供独立只读入口，不恢复下拉选项或新购买权限。
- [ ] 回归覆盖普通用户选择、快速 A/B 切换与响应乱序、跨账号、失效缓存、小屏及键盘，七语言数字格式符合项目规范。
- [x] 安全列表与统计读取涉及数据库时运行真实三数据库验证；完成类型检查、lint、交互测试、适用构建及基线审计。

验收证据对应 checklist F01、F02、F07、F08、F10；独立演示主卡切换，旧资产入口在后续接管前保持可达。
