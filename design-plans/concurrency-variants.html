A

Variant A — Health verdict first

Axis · information hierarchy

One page-level verdict banner answers “is the gateway healthy?” before the admin reads a single number; KPI tiles become the second layer and every detail card visibly recedes.

Key differences

  • Page-top health verdict banner (destructive tone) synthesises over-limit + rejected + queued + degraded into one sentence and four chips; KPI row is demoted to the second read, detail cards live inside a muted “Details” zone with smaller titles.
  • FIX #2Window selector moved into the page header so it visibly governs everything below; the Channel load / EWMA card is live-only — it is hidden when a historical window is selected (same precedent as the Queued badge) and carries a “Live only” chip while Live.
  • FIX #1 / #3Subtitle covers channels and the Over-limit description matches its per-key / per-user siblings.

Variant B — Live rail + evidence column

Axis · layout model

A two-column split puts everything that answers “right now?” (verdict, KPI, queue depth) in a sticky left rail, while the right column holds the evidence: trend on top, buckets and EWMA behind tabs at equal weight.

Key differences

  • Two-column split: sticky left rail = verdict + KPI list + queue depth & settings; right column = trend card with the window selector at its head + a tabbed panel switching between the bucket table and the Channel load table (same card footprint, no page-length stack).
  • FIX #2The selector sits at the top of the reading path with the hint “Applies to every panel on this page”; the EWMA tab follows the window (window-scoped samples, no out-of-window “Last sample” timestamps) and says so on the panel.

C

Variant C — Compact ops console

Axis · density

Same information architecture as today, but every pixel works harder: one tight single column, KPI tiles folded into a toolbar strip, zebra tables with sticky heads, and all explanatory prose parked in tooltips.

Key differences

  • Compact density: page gaps 24px → 12px, card padding trimmed, KPI row becomes a divided toolbar strip (label + value cells, no tile chrome), one-line verdict bar instead of a banner.
  • Tables get zebra stripes + sticky headers and 30% shorter rows; every description (KPI, card, field help, EWMA footnote) collapses into a keyboard-reachable ⓘ tooltip, so the first screen shows ~1.5× more data.
  • FIX #2Window selector lives in the toolbar above everything; the EWMA card is live-only (hidden in historical windows) and labels itself “Live only”.
  • FIX #1 / #3Subtitle covers channels; Over-limit description matches the per-key / per-user siblings.

D

Variant D — Progressive disclosure

Axis · interaction

The default view answers health + trend in one screen; buckets, queue settings and EWMA routing become keyboard-native disclosure blocks that keep their state in the summary line, and queue editing happens inline with Save / Cancel.

Key differences

  • Progressive disclosure: only verdict + KPI + trend are always open. Bucket table, queue settings and Channel load are <details> blocks (native keyboard / screen-reader support) whose summary line carries live numbers, so collapsing costs no information.
  • Inline edit state for the bounded wait queue: values become inputs inside the open block with paired Save / Cancel buttons — no modal, no route change; the block summary shows “Editing” while dirty.
  • FIX #2Window selector sits in the page header; the EWMA disclosure is live-only — it summarises “hidden in historical windows” and its body is gated the same way as the Queued badge.
  • FIX #1 / #3Subtitle covers channels; Over-limit description matches the per-key / per-user siblings.

E

Variant E — Semantic colour, console feel

Axis · visual expression

Same stack and order as today, but the page speaks in state colours: a full-weight verdict band, tinted status chips everywhere a number carries meaning, and 150–300ms ease-out micro-motion that respects prefers-reduced-motion.

Key differences

  • Dark-first preview: this mock is pinned to the dark theme (the header toggle still controls A–D) because the console aesthetic is designed on the charcoal canvas; every semantic colour is checked against WCAG AA on both themes before shipping.
  • Bold semantics: verdict band with 7px colour rail + tinted canvas; utilisation gets tone chips next to the bar (125% / 100% / 80% …); EWMA multipliers become filled chips (green boosted · grey warming · amber penalised); Live gets a pulsing status dot.
  • Micro-motion: cards lift 2px on hover, badges/chips rise 1px, disclosure chevrons and progress bars ease 150–300ms — all disabled under prefers-reduced-motion: reduce.
  • FIX #2Window selector sits in the page header with an explicit scope note; the EWMA panel follows the window (window-scoped samples) and is labelled accordingly.
  • FIX #1 / #3Subtitle covers channels; Over-limit description matches the per-key / per-user siblings.
